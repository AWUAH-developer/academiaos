1. FIX ELECTRON 43 SAFESTORAGE ASYNC API USAGE
==================================================

The current secure-storage.ts implementation shown in the report contains:

if (safeStorage.isAsyncEncryptionAvailable()) {
  const { value, shouldReEncrypt } =
    await safeStorage.decryptStringAsync(buf);
}

This is incorrect according to the Electron 43 API.

safeStorage.isAsyncEncryptionAvailable() returns Promise<boolean>.

It MUST be awaited:

if (await safeStorage.isAsyncEncryptionAvailable()) {

Also decryptStringAsync() returns:

{
  result: string,
  shouldReEncrypt: boolean
}

It does NOT return a property named "value".

Correct the implementation to use "result".

Example structure:

if (await safeStorage.isAsyncEncryptionAvailable()) {
  const { result, shouldReEncrypt } =
    await safeStorage.decryptStringAsync(buf);

  if (shouldReEncrypt) {
    await saveCredential(name, result);
  }

  return result;
}

Preserve the existing secure migration behavior for credentials previously
encrypted through the synchronous API.

Do not allow any plaintext fallback.

Add tests/mocks that prove:

- isAsyncEncryptionAvailable is awaited
- result is read from decryptStringAsync
- shouldReEncrypt rewrites the credential
- unavailable secure storage fails safely
- legacy sync-encrypted credentials migrate to async encryption
